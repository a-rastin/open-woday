## Spec

### (a) Missing / partial
- **Token use partial** — `validation.md:83–84` "Panels use the shared `radiusPanel` / `radiusChip` / `radiusControl` radii and `gap` spacing". `Theme.qml` (a471340) declares all 18 §8.3 tokens, but `radiusControl`, `muted`, `accent`, `dayStripCell` are never applied (the shell has no controls). *Benign*: exact hues deferred to Phase 11 (`requirements.md:168`).

- **Guard check** — `issue 06:20–22`/`validation.md:78–80` want a controlled root-QML-failure check; `main.cpp` is untouched (guard preserved) but no such check/clean-build evidence is recorded in the increment.

### (b) Scope creep
- **Pixel harness** `tests/verify-app-shell.cpp` (507 lines) + `.pro` + `.gitignore` (e673055). Forbidden by `requirements.md:150` "Test frameworks, CI configuration, unit seams…", `:140` "no lower seams, test framework or test doubles", `validation.md:35–39` "Testing whether a specific token constant was declared would be testing implementation details", `issue 06:49–51` "No unit-test framework, UI automation harness … verification remains at the single build-and-launch seam", `:20–22` "without a new test harness". It hardcodes `gap=12`, `radius=18`, hex colours — exactly the unconfirmed "committed screenshot-diff harness" `validation.md:40–43` says needs maintainer confirmation "before /bnvt-ticket" (check 14 leaves it outstanding). *Genuine creep*, despite the `verify-persistence.cpp` precedent at the fixed point.
- **"Quick add" label** `TopBar.qml` (a471340) vs `requirements.md:122` "no … Quick Add parsing". *Borderline/benign*: `validation.md:88` requires a `Ctrl/⌘` modifier label, so a host chip is needed.

### (c) Wrongly implemented
- **Merge-gate seam** — `validation.md:30–34` "`qmake6 && make` produces a binary, and launching that binary opens a window". The harness never launches `open-woday`; it starts its own `QGuiApplication`+`QQmlApplicationEngine` on `offscreen` and loads QML directly — a lower seam. Its comment "No new harness … is introduced" is false, and it asserts internal pixel structure against `validation.md:56–58,63` "Test external behaviour … never on internal structure".
- **Inter fallback** — `requirements.md:119`/`validation.md:84`. `Theme.qml:23` `font: "Inter, system-ui"` claims "Qt resolves the first available family"; QML `font.family` is a single family name, so the comma string is one literal and the Inter/system-UI fallback likely never resolves to Inter.

**Correctly implemented**: three-panel declarative frame, §8.3-valued shared Theme, `resources.qrc` wiring, native chrome/no traffic lights, `Ctrl`/`⌘` property, Sidebar→RightRail fold (`>=720`/`>=560`), no persistence/network/store or `open-woday.pro` change, untouched `main.cpp` guard, no CMake, spec kept an unconfirmed proposal with no fabricated sign-off.
