## Standards

### Documented violations

1. **Soft-delete can retire Notes and Events.** `src/store/ItemRepository.cpp:373–382` follows `parent_id` across every Item kind, including when the root is a Note or Event. Existing repository data can contain these links because the schema does not constrain the kind. `dev-docs/tech-stack.md` §§6.2, 6.4 define the cascade for Tasks and their subtasks.
2. **QML owns scheduling and duration rules.** `src/qml/TaskDetailPane.qml:85–94,886–894` and `src/qml/Theme.qml:70–74` decide which durations are valid and calculate the calendar dates submitted by the scheduling shortcuts. `dev-docs/tech-stack.md` §5.1 places business logic in C++.
3. **Timed Event rows omit scheduling metadata.** `src/app/TodayModel.cpp:606–611` and `src/qml/TodayPage.qml:105–115` produce only `Event: <title>`, omitting the start time shown in the Today reference under `dev-docs/tech-stack.md` §§8.1–8.2, 9.2.
4. **UI labels repeat upstream strings.** `src/qml/TodayPage.qml:83–84` (`New task`) and `src/qml/TaskDetailPane.qml:810,819` (`Add tag`) match guide labels (`dev-docs/app-document.md:650,3404`). `dev-docs/tech-stack.md` §8.4 requires fresh UI strings.
5. **Tests assert internal SQL behavior.** `tests/verify-persistence.cpp:238–249,659–707` asserts the exact rows updated and relies on SQL `SELECT` order for failure injection. `dev-docs/tech-stack.md` §12 calls for observable behavior; the failure assertions can be kept while avoiding that query-order dependency.
6. **Release status is stale.** `README.md:9–12,166–171,229–233` and `CHANGELOG.md:69–76` still describe Phase 4 as current and say Event lines and badge chips are absent. `dev-docs/roadmap.md` §1 requires status updates as work lands; its Phase 2–4 statuses also lag merged work.

## Spec

1. **Incorrect — switching Tasks can overwrite the next Task’s title.** Phase 5 `requirements.md:192`: “rename a Task inline on its row or in the detail pane.” Reproduced in the running QML: edit Task A’s title, then click Task B on Today. SQLite retains A’s old title and saves the edit to B. The model changes the selected ID before the selection handler clears focus and triggers the title commit (`src/app/ItemModel.cpp:358–378`; `src/qml/TaskDetailPane.qml:23–32,149–154,283–286`).
2. **Incorrect — explicitly rescheduled subtasks remain on the old day.** Phase 5 `requirements.md:202`: “moving a Task to another day removes it from the current day’s list and places it on the target day.” Move a child to tomorrow while its parent is due today: the child appears beneath the expanded parent today and as a root tomorrow. Root selection filters by date, but nested rendering includes every child (`src/app/TodayModel.cpp:93–108,555–576`).
3. **Incorrect — scheduling silently shifts times in a daylight-saving gap.** Phase 5 `requirements.md:201`: “add, edit or clear an optional 24-hour due time.” Saving `2026-03-08 02:30` in `America/New_York` succeeds, but Qt normalizes it to `03:30` when both views read it back (`src/app/ItemModel.cpp:55–84,829–851`; `src/app/TodayModel.cpp:63–69`).
4. **Partial — Event rows omit set metadata.** Phase 4 `validation.md:129–132`: “Task and Event lines render … with badge chips for set details.” The Event projection sends only ID, kind and title; a timed Event renders with no time chip (`src/app/TodayModel.cpp:606–612`; `src/qml/TodayPage.qml:105–116`).
5. **Scope creep — cascade can delete non-Task Items.** Phase 5 `plan.md:22–25`: “soft-deleting a Task atomically sets `deleted_at` on the Task and all of its active descendant subtasks.” The repository applies the cascade to every Item kind and follows unrestricted parent links, so an Event or Note linked beneath a Task can also disappear (`src/store/ItemRepository.cpp:357–394`).
