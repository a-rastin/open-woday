## Spec

### Wrong behavior

- **Editing an existing Day note can destroy Block metadata.** The spec requires free writing as ordered Blocks so “the Phase 6 editor inherits the right storage shape” (`requirements.md:179, 226–232`). `TodayModel::loadDayNote()` flattens Blocks to content (`src/app/TodayModel.cpp:194–199`); on edit, replacement deletes existing Blocks and creates plain text rows (`src/store/BlockRepository.cpp:324–350`). Existing Block types, formatting, task links, indentation and IDs would be lost.
- **A failed save can be discarded when changing dates.** The spec says “All writes go straight to SQLite with no in-memory-only state” (`requirements.md:233–235`). On failure, `setDayNoteText()` leaves the attempted text in the editor (`src/app/TodayModel.cpp:205–217`, `src/qml/TodayPage.qml:67–72`). Selecting another date then loads another note without resolving that failed write (`src/app/TodayModel.cpp:220–234`), replacing the unsaved text.

### Missing or partial requirements

- **Task creation is not available on the page.** The plan requires a “minimal write path … to place a Task/Event line on a day” (`plan.md:73–74`). `addTask()` exists (`src/app/TodayModel.cpp:137–152`), but no QML control calls it. Task/Event rendering, badges and check-off are also outstanding; these belong to later planned slices, so their absence is a phase-completion gap rather than a defect in a completed slice.
- **The launch/restart seam is not yet covered by the Colab runner.** Validation calls for launching the app, writing, restarting and observing the rendered state (`validation.md:30–35`). The runner builds and runs `verify-persistence` (`tests/colab_gpu_verify.py:98–118`), but does not build or launch the app. This is a phase-completion gap, not evidence that the unfinished phase has failed its final gate.

### Scope

- **README and changelog changed:** `validation.md:164–165` says “README / CHANGELOG / roadmap are not edited in this phase,” but the diff changes `README.md` and `CHANGELOG.md`. These changes include documentation of the separately introduced testing rule, so the deviation may be intentional.
